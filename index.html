为什么 FastD

一套小内核，覆盖真实 API 服务的主链路

从请求进入、路由匹配到中间件和响应，框架只保留必要的部分。需要缓存、数据库或服务治理时，再按需组合组件。

双运行时，不锁死部署

同一套业务代码可在 CGI / FastCGI 与 Swoole 6 之间切换，按团队现有部署体系选择。

PSR 边界，组件可替换

请求、响应、容器、事件和中间件遵循 PSR，外部实现可以和框架一起工作。

按需引入，不背全家桶

核心保持精简。缓存、MedooDB、微服务集成和部署能力放在独立包里，用什么装什么。

为长连接和并发准备

Swoole 运行时提供协程、并行编排和 SSE，适合实时接口与聚合型 API。

常见问题

在决定之前，先把边界问清楚

FastD 是完整全栈框架吗？

不是。FastD 面向 API 场景，核心提供应用调度、HTTP、路由、中间件、容器、配置和事件。缓存与数据库等能力按需安装。

必须使用 Swoole 吗？

不是。FastD 同时支持 CGI / FastCGI 和 Swoole 6。Swoole 提供常驻 Worker、协程和长连接，CGI 适合传统部署体系。

FastD 适合微服务吗？

适合把 FastD 用作 HTTP API 服务、BFF 或聚合层。服务注册、配置中心和链路能力通过可选集成包接入，核心不内置完整治理平台。

如何扩展 FastD？

通过 ServiceProvider、PSR 中间件、HTTP 客户端和独立组件扩展，不需要修改框架入口。

运行 FastD 需要什么版本？

PHP 8.4.1 或更高版本；使用 Swoole 运行时还需要 Swoole 6 或更高版本。CGI / FastCGI 环境不需要 Swoole。

从哪里开始使用？

从快速开始创建项目、定义第一条路由并启动服务；组件细节和常见场景可以在同一文档站继续查阅。
